# Moving the sign-in email sender to `mail.blazn.frontro.com`

Sign-in codes are sent through Resend from `no-reply@mail.blazn.benpelo.com`,
the only domain verified in the Resend account. This directory prepares the
move to `no-reply@mail.blazn.frontro.com`. Nothing here has been applied.

## What cannot be prepared in advance

The DKIM public key is generated by Resend when the domain is added, and the
API key in the cluster is send-only (`restricted_api_key`), so it cannot add or
read domains. Someone with access to the Resend dashboard does step 1.

## Records

`frontro.com` is hosted in Route 53. These are the records the current domain
uses, renamed for the new one. **Confirm each against what Resend shows for
the new domain**: Resend is the source of truth, and its record set has
changed before.

| Name | Type | Value | Purpose |
|---|---|---|---|
| `send.mail.blazn.frontro.com` | CNAME | `send.forge.rmta.net` | Return path: provides the bounce MX and SPF |
| `resend._domainkey.mail.blazn.frontro.com` | TXT | `p=…` from Resend | DKIM public key |
| `_dmarc.mail.blazn.frontro.com` | TXT | `v=DMARC1; p=none;` | DMARC, same policy as `_dmarc.frontro.com` |

`*.frontro.com` is a wildcard CNAME to Fastly, so all three names resolve to
Fastly today. Explicit records at these names take precedence over the
wildcard; nothing has to be deleted first. No record is needed at
`mail.blazn.frontro.com` itself.

`route53-change-batch.json` holds the three records with a placeholder for the
DKIM value.

## Steps

1. **Resend dashboard → Domains → Add domain** `mail.blazn.frontro.com`, same
   region as the existing domain. Copy the DKIM value and check the other
   records against the table above.
2. **Create the records.** Put the DKIM value in the change batch, then:

   ```sh
   aws route53 list-hosted-zones-by-name --dns-name frontro.com --query 'HostedZones[0].Id' --output text
   aws route53 change-resource-record-sets --hosted-zone-id ZONE_ID \
     --change-batch file://infra/frontro/sender-domain/route53-change-batch.json
   ```

3. **Check the DNS**, then press Verify in Resend and wait for "Verified":

   ```sh
   infra/frontro/sender-domain/verify.sh
   ```

4. **Switch the sender.** In `infra/frontro/blazn-test/deployment-api-dev.yaml`
   change `EMAIL_FROM` to `Blazn <no-reply@mail.blazn.frontro.com>`, then:

   ```sh
   kubectl diff -k infra/frontro/blazn-test
   kubectl apply -k infra/frontro/blazn-test
   ```

   Resend sending keys can be restricted to one domain. If the current key
   is, create a key for the new domain and replace `resend_api_key` in Secret
   `api-dev-email` before switching. The key is due for rotation anyway (plan
   item M0.5), so this is the moment to do both.
5. **Prove delivery to a real mailbox.** `qualify-flows.py` cannot: its
   addresses go to the capture inbox, not through Resend. Sign in once with a
   real address and check the message headers for `dkim=pass` with
   `d=mail.blazn.frontro.com` and `dmarc=pass`.
6. **Update the sender address** in `docs/delivery/hosting-runbook.md`,
   `docs/delivery/try-the-hosted-environment.md` and
   `docs/delivery/end-to-end-plan.md`.
7. Leave the old domain verified in Resend for a few days, then remove it and
   its three records under `mail.blazn.benpelo.com`.

## Rolling back

Set `EMAIL_FROM` back to `Blazn <no-reply@mail.blazn.benpelo.com>` and apply.
The old domain keeps working as long as it stays verified in Resend.
